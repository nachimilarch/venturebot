Vaartabot · CRM Integration API

Send WhatsApp promotions from your CRM

Use the Vaartabot API to send approved template messages, manage templates, receive real-time reply notifications, and track credits — all from your own CRM or marketing tool.

Protocol HTTPS / REST Format JSON Auth API Key Cost 1 credit per message
Base URL https://vaartabot.com/api/v1

Authentication

All API v1 requests require an API key in the X-API-Key header. Generate keys from your Vaartabot dashboard → API Reference → API Keys.

⚠️ Keys are shown only once at creation. Store them immediately in your CRM's environment config. If a key is lost, revoke it and generate a new one.
HTTP
GET /api/v1/credits/balance HTTP/1.1
Host: vaartabot.com
X-API-Key: vb_a1b2c3d4e5f6...
Content-Type: application/json

Key format

All keys start with vb_ followed by 40 hex characters. The 12-character prefix is shown in your dashboard for identification.

Errors & Status Codes

Every response has a top-level success boolean. On failure, error has a human-readable message.

JSON — error shape
{
  "success": false,
  "error":   "Insufficient credits. Purchase more at https://vaartabot.com/billing",
  "creditsBalance": 0  // only on 402
}
StatusMeaningHow to handle
400Bad RequestMissing or invalid fields — check the error message
401Invalid or missing API keyCheck X-API-Key header; regenerate if lost
402Insufficient creditsDirect user to vaartabot.com/billing
404Resource not foundCheck the ID or phone number in your request
422WhatsApp/Meta rejected the requestVerify template name, language, variable count, or template status
429Rate limit exceededBack off and retry after the Retry-After header value (seconds)
502Meta API errorMeta Graph API returned an error — retry or check Meta status page
500Server errorRetry with exponential back-off; contact support if persistent

Messaging

Send approved WhatsApp template messages and read inbound replies. Each successful send costs 1 credit.

💡 Phone numbers are auto-normalised — 9876543210 (10-digit) becomes 919876543210 (E.164).

Send a WhatsApp template message to one recipient. Deducts 1 credit on success.

{ "success": true, "message": "Webhook deleted" }

Push payload format

Vaartabot sends this JSON body to your registered URL for every subscribed event. The raw body is signed with HMAC-SHA256 using your subscription secret.

JSON — event payload
{
  "event":     "message.received",
  "tenant_id": 42,
  "timestamp": "2026-07-12T09:30:00.000Z",
  "data": {
    "message_id":  "wamid.HBgM...",
    "from":         "919876543210",
    "type":         "text",
    "text":         "I want to book an appointment",
    "received_at":  "2026-07-12T09:30:00.000Z"
  }
}

Verifying the signature

Every request includes an X-Vaartabot-Signature header in the format sha256=<hex>. Always verify it before processing the event.

Node.js — Express
const crypto = require('crypto');

// IMPORTANT: parse as raw Buffer, not JSON
app.post('/webhooks/whatsapp', express.raw({ type: 'application/json' }), (req, res) => {
  const sig      = req.headers['x-vaartabot-signature'];
  const expected = 'sha256=' + crypto
    .createHmac('sha256', process.env.WEBHOOK_SECRET)
    .update(req.body)
    .digest('hex');

  if (!crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(sig))) {
    return res.status(401).send('Invalid signature');
  }

  const event = JSON.parse(req.body);
  console.log('Reply from', event.data.from, ':', event.data.text);
  res.sendStatus(200);  // acknowledge within 8 s
});
⚠️ Your endpoint must respond with any 2xx status within 8 seconds. Slower responses count as failures. A failure_count counter increments on each failed delivery — monitor it with GET /webhooks.

API Key Management

These endpoints use a Vaartabot session JWT in Authorization: Bearer — not an API key. Use them to let your CRM users manage their own keys from inside your dashboard.

Base path (JWT auth)
https://vaartabot.com/api/api-keys
GET /api-keys List keys ▶

Returns all API keys for the tenant. Full key values are never returned — only the 12-char prefix.

JSON · 200
{
  "success": true,
  "data": [
    {
      "id": 3, "name": "My CRM Key",
      "key_prefix": "vb_a1b2c3d4e5",
      "is_active": true,
      "last_used": "2026-07-12T07:30:00.000Z"
    }
  ]
}
POST /api-keys Generate a new key ▶

Creates a new API key. The key value is shown only once — store it immediately.

JSON · 201
{
  "success": true,
  "message": "Save this key now — it will not be shown again.",
  "data": {
    "name":      "Zoho CRM Integration",
    "key":       "vb_a1b2c3d4e5f6789abc...",
    "keyPrefix": "vb_a1b2c3d4e5"
  }
}
DEL /api-keys/:id Revoke a key permanently ▶

Permanently deletes a key — any CRM using it immediately gets 401 errors. Use PATCH /api-keys/:id with is_active: false to temporarily disable instead.

cURL
curl -X DELETE https://vaartabot.com/api/api-keys/3 \
  -H "Authorization: Bearer YOUR_SESSION_JWT"

Credit Purchase Flow

Credits are bought in the Vaartabot dashboard — not via API. Guide your users through this flow:

#WhoAction
1ClientLogs into vaartabot.com → Billing → picks a credit package
2VaartabotCreates a Cashfree payment order, redirects to checkout
3ClientPays via UPI / card / netbanking
4CashfreeSends webhook — credits added to account automatically
5Your CRMPolls GET /api/v1/credits/balance to confirm new balance and unlock campaigns
